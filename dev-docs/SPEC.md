# Job Vaccum 产品规格

版本：v0.7 产品设计基线

更新日期：2026-10-20

状态：待实现。本文描述桌面产品的目标行为，不代表当前 CLI 已具备这些功能。

## 产品定位

Job Vaccum 是基于现有岗位检索 pipeline 的 macOS Apple Silicon（arm64）桌面应用。它将 JobSpy 检索、规则筛选、历史去重、LLM 个性化评分、结果浏览和定时运行集成到一个本地软件中。

项目主要用于个人作品展示和开源分享，面向愿意自行配置模型 API 和可选代理的技术用户。目标是在可控的开发投入下，提供完整、直观、可演示的使用流程。公开版本使用较小的默认检索规模，不要求复刻私人版本的全部配置、运行规模和外部自动化。

用户使用自己提供的 LLM API 地址、Key 和模型完成 query 生成、评分模板生成与岗位评分。首版不提供托管模型服务、用户账号或云端数据库。

首版界面使用英文，不做多语言版本。预置美国城市，用户可以增删或修改地点，并填写 Indeed 使用的国家。本文使用中文描述产品行为，不代表界面文案语言。

产品侧重批量岗位发现与投递准备：按多个方向展开批量抓取，统一筛选、去重和可选自动评分，再批量整理、导出待投岗位。适用于后续批量投递的工作流；实际投递可由用户已有 skills 或其他工具完成，首版不增加 skills 调用接口、自动投递或简历定制功能。

核心使用路径：

> 配置模型 → 描述求职方向 → 选择筛除条件 → 粘贴简历文本生成评分模板 → 执行检索 → 浏览岗位 → 将感兴趣的岗位加入投递清单 → 手动管理状态。

## 界面结构

侧边栏主入口为「岗位发现」「投递清单」「运行记录」；「设置」独立放在底部。首次使用进入配置引导。岗位详情为共用的右侧抽屉，不单独占据导航入口。

| 入口 | 默认内容 | 核心操作 |
| --- | --- | --- |
| 岗位发现 | 检索结果与方向导航 | 搜索、按批次筛选、筛选、排序、查看详情、加入投递清单、手动评分 |
| 投递清单 | 用户主动选择的岗位表格 | 修改状态、编辑备注、手动评分、筛选、排序、移出、导出 |
| 运行记录 | 运行计划、每轮执行的进度、结果和诊断 | 新建／编辑计划、在计划内立即运行、停止、续跑、查看本轮新增岗位 |
| 设置 | 分页组织的配置 | 手动修改、连接测试、AI 重新生成 |

两个页面都使用紧凑的单行列表，每行一个岗位，便于高密度浏览和批量操作；岗位发现突出评分理由，投递清单突出状态与备注。完整 JD 在右侧详情抽屉查看，不做卡片视图或列表内 JD 摘要。二者共用列表组件、岗位内容、详情抽屉与数据查询能力，避免开发两套内容系统。

界面英文名：岗位发现为 Jobs，投递清单为 Shortlist，运行记录为 Runs，设置为 Settings，搜索方向为 Searches。内部标识（scope=discover/applications、applications.* 命令、directions 表）不随界面名称改变。

界面状态文案：清单状态为 New、Applied、OA、Interviewing、Offer、Rejected、Ghosted；评分状态为 Unscored、Queued、Scoring、Scored、Failed。

- 日期与时间：全应用使用数字格式、24 小时制，日期时间为 `10/19 21:29`，只显示日期时为 `10/17`；不是今年的日期写成 `2025/12/03`。表格、详情、Runs、批次选项和提示条一致。
- 默认窗口 1280×800，最小 640×480。运行功能在 M2 加入前，侧边栏和窄条不显示 Runs 入口。

- 清除筛选：存在筛选条件时，筛选标签和「+ Filter」之后出现「Clear all」，一键清空全部筛选；与取消勾选无关。
- 分页：筛选行右侧、Columns ▾ 左边显示「1–50 of 214 ‹ ›」，到首页或末页时对应箭头变灰；点击数字弹出每页条数（50、100、200）和首页／末页。
- 操作提示：窗口右下角的小号黑底提示条，约 8 秒后消失，鼠标悬停时保持。可撤销的操作（移出清单、批量改状态）带「Undo」链接，⌘Z 同效；其他提示带相关链接（View、Show in Finder）；失败提示用深红底并写明原因。所有链接样式统一，不做成按钮框。
- 确认框只用于影响大且不可撤销的操作：删除搜索方向、清理岗位数据。破坏性按钮用红色并写明动作，默认焦点在 Cancel，Esc 取消。移出清单、改状态、改名、加入清单都不弹确认。
- 空状态与错误：加载超过约 0.5 秒才显示骨架行；「还没有岗位」与「筛选后没有结果」文案不同，后者提供 Clear filters；投递清单为空时提示从 Jobs 加入。单次请求失败在卡片顶部显示横幅并可重试；后台进程意外退出时挡住界面，只提供 Quit；启动失败为整窗口错误页，显示原因、数据目录（Show in Finder）和 Quit。所有错误先写人能读懂的原因和处理办法，错误代码用小号灰字放在后面。

## 首次配置引导

### 模型连接

首版只提供 Custom 自定义连接，不提供 Gemini、Claude、OpenAI、OpenRouter、DeepSeek 等提供商预设。用户选择底层协议，填写 API Base URL、API Key 和模型 ID，并执行连接测试。

四种协议均纳入首版：

| 协议 | 调用接口 |
| --- | --- |
| OpenAI Chat Completions | Chat Completions 请求和响应格式 |
| OpenAI Responses | Responses 请求和响应格式 |
| Anthropic Messages | Messages 请求和响应格式 |
| Gemini generateContent | generateContent 请求和响应格式 |

采用直接 HTTP 请求，不要求接入提供商 SDK。页面按协议提供 Base URL 的填写示例，说明应包含的版本路径和自动拼接的接口后缀；不混用 Base URL 与完整请求地址。

提供基础请求参数，包括 temperature、最大输出 token、推理强度或思考配置等；协议强制要求的字段标为必填，其余可选。留空不发送，填写后按所选协议的字段结构发送；不做模型能力识别、模型白名单、自动删参或提供商特殊适配。字段的简单说明和示例随协议切换，不支持的模型参数由服务端返回错误，用户自行调整。提供商预设、默认模型及更细的兼容处理以后再加。

连接失败时显示可操作的错误信息，允许修改后重试；不丢失已填写的非敏感配置。所有后续 AI 功能复用这份连接设置。

### 求职方向

第一个业务页面提供对话框，让用户描述希望寻找的岗位方向、城市或地区及必要偏好。AI 根据内置 prompt 生成结构化搜索方案，默认创建一个方向和 2～3 条 query。信息不足时允许简短追问，不做复杂的自主 Agent 流程。

生成结果以可编辑的方向、query 和城市列表展示。用户可以增加、删除或修改 query 与城市；后续也可增加新的方向。AI 不应擅自将未表达的条件设为硬限制。

生成 prompt 需要约束目标平台支持的检索表达式。方向名是用于展示的名称，query 是实际传给检索器的表达式，二者分别保存。

### 筛除条件

第二个业务页面提供常见筛除条件的开关、多选和少量数字输入，包括岗位层级、必需经验年限、岗位类型、明确资格限制和公司排除名单。

每项说明其具体作用。例如使用「排除明确不提供 sponsorship 的岗位」，避免只有含义不清的「签证筛选」标签。条件未知与条件明确冲突需要区分。

### 个人评分标准

评分配置独立于求职方向对话。用户直接粘贴简历文本，辅以少量常见条件按钮，例如是否需要签证支持、毕业时间等。已经填写的条件直接复用，不重复收集相同信息。

AI 依据简历、已选条件和内置模板生成一份 Markdown 评分标准。用户可以查看、修改并保存；不要求继续通过聊天完成配置。简历中不存在的身份或资格信息不能由模型自行推断。

首版使用一份全局评分模板，可描述多个求职方向，不为每个方向设置独立评分模型或评分体系。首版仅支持粘贴简历文本，不提供文件上传、PDF／Word 解析或 OCR。

### 检查并开始

展示搜索方向、query、城市、筛除条件、评分模板和当前检索模式。用户可返回修改，再选择立即执行或配置运行计划。

引导生成的是持久配置，后续在设置中可以找到、编辑或重新生成。配置未完成时保存草稿，下一次打开可继续。

默认按步骤完成全部配置，每一步也可以跳过（Skip），之后在设置中补齐。跳过模型连接时，求职方向改为手动填写，评分模板步骤视为跳过。跳过评分模板时自动评分随之关闭，检查页显示「Auto-scoring: Off — no rubric」，仍可开始运行，新岗位为未评分。没有评分模板时，自动评分开关和评分按钮不可用并说明原因；之后在设置中保存评分模板时询问是否开启自动评分，不自动开启。没有启用的方向和 query 时不能开始运行。

## 搜索方向与 query

一个方向包含稳定 ID、可编辑名称、启用状态、显示顺序和一组 query。每条 query 可以编辑、删除或启停。城市作为独立列表维护，首版默认由所有方向共用，并支持检索半径。预置美国城市，用户可以自行编辑地点文本。

提供 Indeed 国家填写项，默认 `usa`，传给 JobSpy 的 `country_indeed`；页面说明需使用 JobSpy 支持的国家名称。LinkedIn 只使用 `location`，不使用该国家字段。修改城市不会自动推断或修改 Indeed 国家。首版不做多语言筛选规则适配。

方向可以拖动排序，但顺序只影响导航展示，不决定岗位归属，也不参与评分或去重。

检索任务由启用的 query、城市和平台展开。首版沿用现有 LinkedIn、Indeed 接入，采用 ARCHITECTURE 中锁定的新版 JobSpy 提交，不因为库支持其他平台就自动扩大支持范围；不增加 offset 分段或分页恢复。

运行前显示展开后的任务数量。不设置任务总量或评分数量预算，不静默忽略用户配置的 query 或城市；检索深度和并发由默认／高级模式参数决定。

修改搜索设置只影响新运行。已经开始的运行使用启动时的配置快照，续跑不因设置变化而重新编号或改变任务范围。

重命名方向后，所有关联岗位显示新名称。删除方向时删除其 query 和全部方向标签关联，不删除岗位或投递清单记录；岗位仍可在「全部」中查看。不保留已删除方向作为岗位的历史标签。方向变更与岗位的配置留存期限无关。

## 岗位发现

岗位发现是检索结果池。用户可以查看本轮、近期或仍在留存期内的历史结果，并按方向浏览。它不只展示高分岗位，低分、待评分和评分失败必须能与成功评分结果区分。

「全部」视图中，每个岗位实体只显示一次。在方向视图中，显示所有命中该方向的岗位；同一个岗位允许出现在多个方向视图中。

列表默认显示评分、岗位标题、公司、评分理由、方向、地点和发布时间；岗位类型、来源和发现时间可在列菜单中打开。默认按发现时间从新到旧排序，可切换评分等排序；完整规则见下节。

核心操作包括搜索、方向切换、按批次查看、地点与评分筛选、排序、查看详情、打开申请链接、加入投递清单、手动评分和导出 CSV。

加入后按钮变为「已加入」。从投递清单移出后，可再次加入。首版不另建收藏池，使用加入清单表达用户的处理意图。

硬筛除记录直接丢弃，不进入岗位发现，不持久保存完整条目或原文证据，不提供查看、恢复或重新送评流程。运行页面仅展示简单的筛除数量统计。

## 批量浏览、筛选与排序

岗位发现支持逐条勾选、Shift 按当前可见顺序连续选择，以及选择按钮的全选当前页和按条件勾选（见「窗口布局与列表」）；清单复用相同选择行为。有勾选时显示「N selected」，点选择按钮的方框取消全部勾选。岗位发现提供批量加入清单，已加入项不重复创建；清单提供批量改状态和批量移出。选择限当前页，换页、改变筛选或排序时清空，避免隐藏选中项；不增加跨全部结果的隐式全选。

详情抽屉提供上一条／下一条，按当前页排序连续浏览，到边界禁用；保持列表滚动位置和选中岗位。支持上下键或 J/K 切换岗位、S 加入清单、O 打开申请链接、Esc 关闭详情，提供快捷键帮助。输入框、可编辑内容及弹窗内不触发列表快捷键。操作后岗位仍符合筛选则保留位置并更新「已加入」；不再符合时选中下一条，末尾选上一条。后台抓取和评分更新提示「结果已更新」，不自动重排正在浏览的列表；用户刷新后重查排序，尽可能按岗位 ID 保持选中项。

两个页面分别记住筛选、排序、每页条数、列宽和显示的列，侧边栏折叠状态全局记住；均保存在本机 UI 偏好，重启后保持，不新增业务表。页面切换保留会话内页码、滚动及选择焦点，重启后从第一页恢复筛选。方向或运行已删除时清除对应失效条件并提示。筛选条件可逐项移除、全部清空，展示匹配总数；空结果区分尚无岗位与无匹配条件，并提供清空筛选入口。

筛选范围如下；已生效的条件在筛选行显示为可移除标签，其余通过「+ Filter」添加，不引入规则编辑器：

| 筛选 | 行为 |
| --- | --- |
| 搜索文本 | 匹配标题、公司、地点，不做语义检索 |
| 方向、来源平台、公司、地点、岗位类型 | 支持多选；同一维度 OR，不同维度 AND；来源只要命中任一来源即可 |
| 评分范围及评分状态 | 0～10；未评分、排队中、评分中、成功、失败分别选择；范围仅匹配已有分数 |
| 发现时间、发布时间 | 快捷时间范围和自定义日期范围；发布时间缺失单独可选，不用发现时间冒充 |
| 批次 | 下拉多选一个或多个抓取运行，另有 All；选项显示运行开始时间和新增数，例如「10/18 09:00 · 42 new」。只显示在所选运行中首次发现的岗位：每个岗位只属于首次发现它的那一轮，后续运行的历史重复命中不计入；不预设运行间隔。手动评分运行不列出。运行记录已清理的岗位只在 All 中可见 |
| 是否加入清单 | 全部／未加入／已加入，岗位发现使用 |
| 清单状态、加入时间、状态或备注更新时间 | 投递清单使用 |
| 薪资 | 可选有薪资／无薪资；数值范围必须同时指定币种和计薪周期，按已知薪资区间与筛选区间重叠匹配，缺失端点视为开放端点；完全未知不匹配数值范围，不折算汇率或年薪 |

排序通过点击列表头完成：可排序的列为评分、岗位标题、公司、地点、岗位类型、发布时间、发现时间；清单额外有状态、加入时间和更新时间。第一次点击时，评分和时间列按降序，文字列按升序；再点切换方向；当前排序列的表头显示箭头。状态按 New → Applied → OA → Interviewing → Offer → Rejected → Ghosted 的流程顺序排列，不按字母。评分理由、备注、方向和来源列不能排序（方向和来源可能有多个值）。一次只按一列排序，发现页默认发现时间降序，清单默认加入时间降序，各页记住上次的排序。不增加多列排序编辑器或跨币种薪资排序。所有排序固定追加 job_id 作为同值次序，空值无论升降序均置后。已有旧分但本次重评失败时仍可按旧分排序/过滤，同时明确显示失败状态与原评分时间。

列表响应包含完整匹配数量；分页、统计与 CSV 导出共用相同筛选规则，导出「当前筛选」覆盖全部匹配结果，不仅当前页。上述交互不新增收藏池、隐藏岗位状态或网页 iframe 预览。

## 岗位详情

岗位发现与投递清单共用详情抽屉，至少包含：

- 公司、标题、地点、岗位类型、发布时间和可用薪资信息。
- 完整 JD、来源平台和可用的岗位申请链接。
- 评分、简短评分理由、评分时间，以及未评分或评分失败等明确状态；可显示使用的模型 ID。
- 命中的多个方向和 query 来源。
- 加入投递清单，或已加入后的状态与备注操作；两个页面均提供评分（已有分数时为重新评分）。

完整 JD 以 Markdown 渲染（抓取时 JobSpy 输出 Markdown），保留标题、分段和列表；不渲染原始 HTML，不执行内容中的脚本，链接由系统浏览器打开。不为显示额外清洗或改写 JD 文本。

不将匹配分数表述为面试概率。不推断缺失的薪资、身份要求或资格条件。外部申请链接交由系统浏览器打开。外部直链允许缺失（新版 LinkedIn 可能仅有平台页面链接），此时打开平台岗位页面，不额外抓取或猜测公司申请链接。

## 投递清单

投递清单是用户主动维护的第二个池子，代表准备投递或已经进入跟踪过程的岗位。只有用户从岗位发现主动加入的岗位进入清单。

与岗位发现共用同一表格组件，默认列为评分、岗位、公司、状态、备注、方向、地点和加入时间；评分理由、发布时间、岗位类型、来源、更新时间和申请链接可在列菜单中打开。状态在行内或详情的下拉菜单中修改，选中即保存。备注在详情中为多行输入框，点到别处或 ⌘↩ 保存，Esc 放弃；在表格中双击备注格或按 Return 进入单行编辑，Return 保存，Esc 放弃。列宽和显示的列可调整（见「窗口布局与列表」），不提供公式列或自定义字段。

基础状态为 New、Applied、OA、Interviewing、Offer、Rejected、Ghosted（分别对应未投递、已投递、收到在线测评、面试中、拿到 offer、被拒、无回音）。不想要的岗位直接移出清单，不设「不感兴趣」状态。加入时默认为 New，状态可直接切换，不强制按流程顺序推进，并记录最近更新时间。可勾选多条一次改为同一状态，只改状态及更新时间，不改备注；提示条提供 Undo，把这些岗位的状态和更新时间改回原值。

支持搜索、筛选、排序和 CSV 导出。表格提供逐行勾选、当前页全选及批量删除操作；这里的「删除」表示从投递清单移出所选岗位。移出只删除清单关系及其当前管理信息，不删除岗位发现中的实体，也不修改查重记录；移出不弹确认，提示条提供 Undo：撤销时按移出前的状态、备注、加入时间和更新时间恢复清单记录。提示条消失后再次加入作为一条新的清单记录处理，不恢复旧备注和状态。

同一岗位只能有一条有效清单记录。无论从哪个方向或哪次运行加入，重复操作均返回「已在投递清单」，由数据库唯一约束保证，不只依赖按钮禁用。

已加入的岗位再次被检索到时，新增方向或来源不能覆盖用户维护的投递状态和备注。

手动评分见「评分模板与结果」；成功结果两个池子共用，不改变清单状态和备注。

用户主动加入投递清单的岗位不参与设置页手动清理或 自动清理。保留其完整 JD、评分、来源、查重身份、状态和备注，直到用户在投递清单页面主动移出。移出后恢复普通岗位的清理规则，首次发现时间不重置，具体见「数据模型与留存」。

## 基础去重与多方向标签

### 岗位实体与来源

在被基础去重规则识别为同一岗位的范围内，一个岗位只保存一个实体。该实体可以关联多个平台来源、多个 query、多个搜索方向和多次运行。

例如一个岗位同时被「AI 工程」和「Python 后端」命中，则两个方向中都能看到它，但「全部」中只有一条记录。调换两个方向的显示顺序，不改变岗位实体、标签或评分。

### 去重边界

沿用现有 pipeline 已使用的去重判断，不另建更严格的身份冲突策略、模糊语义去重或手工合并工具。规则细节以现有代码及 FILTERING-AND-DEDUP.md 为行为参考和验收对照，包括：

- 平台加岗位 ID 去重、规范化岗位直链去重。
- 同轮跨平台同公司＋同标题合并，保留先入库代表、合并其他平台来源；这一步不额外比较地点、招聘编号或不同直链。
- 历史来源 ID、直链、公司＋归一化 JD 匹配。
- 同轮公司＋归一化 JD 精确内容比较；该内容阶段沿用不同有效外部直链分别保留的规则，不反向恢复前面已合并的记录。

产品仅取消固定方向优先级，并把历史匹配从「丢弃本轮副本」改为「关联已有实体」：已存在的岗位不重复插入、不重复评分，只补充来源、方向和本轮命中关系。不刷新首次发现时间，不自动更新已有 JD 或覆盖评分，不做 JD 版本管理。

同轮合并保留来源集合和命中关系。每个 query × 城市 × 平台抓取任务返回 DataFrame 后筛选、去重、入库，不等待整轮完成；同轮去重同时检查本轮已入库岗位。批内按返回顺序取首个通过筛选的有效代表，跨批次先入库者固定，不再按平台、方向或后来的正文完整度替换。并发返回顺序可以影响代表内容，不承诺与整轮集中去重结果完全一致；方向显示顺序不参与算法。后续只补充来源及其链接、query、方向、身份和运行关联。

### 不设置主方向

公开产品取消现有固定的 AI、ML、DE、Backend 主分类优先级，不设置用户可调的合并优先级，也不要求一个岗位只归入一个方向。

方向顺序调整不触发重新抓取或重新评分。多个 query 命中同一岗位不应重复提交同一份评分输入。

岗位发现去重与投递清单防重分别处理：前者确定实体身份，后者对岗位实体 ID 建立唯一约束。基础去重未识别出的跨平台重复仍可能作为不同实体加入清单，首版允许用户自行移出其中一条。

## 筛除与评分

### 筛除规则

将现有按个人需求固定的常用规则转为可配置项，包含层级或标题规则、经验年限、岗位类型、签证或工作授权等明确资格限制。针对专业方向的排除项可放入折叠区域。

公司排除继续使用可编辑名单，支持粘贴多个名称。规则基于 JD 和岗位字段，不基于模型既有评分反向决定是否筛除。

筛除发生在付费评分前。命中规则的抓取记录直接丢弃，仅累计总数和按规则／方向的筛除数量，不持久保存被筛条目和证据。再次抓取的副本被筛除，不删除数据库中已有的岗位或清单记录。不扩展通用规则语言或筛除记录管理。

产品提供通用模板，不将开发者的学校、毕业时间、经历或身份条件硬编码为所有用户的默认值。

### 评分模板与结果

提供全局「自动评分」开关，默认开启，设置页可修改，运行前摘要显示其值。开关写入运行配置快照，仅影响新运行，续跑沿用原值；不做每个方向/query 的独立开关。关闭时仍正常抓取、筛选、去重和入库，新岗位显示「未评分」，不登记评分任务、不调用评分 LLM；已有分数保持不变。再次开启不自动补评历史岗位，也不改变旧运行；用户可在岗位发现或投递清单中用「Score」手动评分。手动评分不受自动评分开关限制，仍需有效模型配置和评分模板。关闭自动评分不禁用 AI 引导；引导中跳过评分模板时自动评分随之关闭，见「首次配置引导」。

沿用 0～10 分和简短理由的输出形式，表示个人投递优先级。分数为 0 是有效模型判断，评分请求失败则是独立状态。

AI 生成、用户手工编辑和从示例开始，最终都落成同一份可编辑的 Markdown 模板。重新生成先形成草稿，再由用户选择应用，不直接覆盖手工修改。

开启自动评分时，通过筛选和去重的新岗位全部送评，不设评分数量上限、API 用量预算或费用管理。新岗位与待评分任务一起提交后即可派发，抓取后续任务与评分重叠。评分使用固定岗位内容和运行快照模板，不依赖后续增加的来源/方向标签。每个新岗位在本轮对应一个评分任务，后续 query 命中不重复创建；不同岗位不共享请求或复制评分，续跑跳过已成功评分。所有调用仍受全局并发/RPM 控制，不因批量入库突发派发。

修改模板、模型或调用参数不自动重评已有岗位，不显示「版本过期」，不建设模板／模型版本管理。显示实际评分时间，用户自行判断是否需要重评。

### 手动评分

岗位发现和投递清单的工具栏各有一个「Score」按钮，菜单包含：

- Score selected (N)：对当前勾选的岗位评分，有勾选时可用。
- Score all N matching…：对当前筛选的全部匹配结果评分（不限当前页），执行前确认将调用模型的岗位数量。

详情抽屉对单个岗位提供同样的评分操作。只评未评分岗位、换模板或模型后全部重评、只重评某方向或某分数段等场景，都通过先筛选（评分状态、方向、分数等）再评分完成，不另设模式。没有分数的岗位为首次评分，已有分数的为重新评分，使用同一入口。

评分使用当前模型配置和评分模板，作为一次手动评分运行执行：创建时固定岗位集合，与抓取运行共用「同时只有一轮」的互斥和全局并发/RPM，可停止，进度在运行记录查看。成功后更新分数、理由和评分时间；失败时保留原有成功评分并提示本次失败。没有有效模型配置或评分模板时按钮不可用并说明原因。设置页不提供重评入口。

评分失败允许有限重试和续跑。已经成功的结果保留，部分失败不阻止浏览已有结果或导出。不得将失败请求记成 0 分。

## 运行模式、检索深度与代理

### 默认模式

默认模式使用固定参数，界面不开放检索深度、并发、RPM、重试和代理调度参数调节：

| 参数 | 默认行为 |
| --- | --- |
| Indeed 抓取目标 | 每条 query × 城市任务 100 条 |
| LinkedIn 抓取目标 | 每条 query × 城市任务 10 条 |
| LLM 调用并发 | 1 |
| LLM 请求速率 | 保守的固定 RPM，具体数值在实现验证时确定 |
| 检索并发与重试 | 保守固定值，保留超时、有限重试和停止能力 |

抓取目标不保证实际返回数量。默认值基于当前使用经验，不承诺 Indeed 或其他平台永不限流。LinkedIn 存在限流，界面帮助和文档提示较大规模检索建议使用代理。

代理为可选项，默认模式可以直连或填写普通代理地址。普通代理仅提供转发，不具备 App 控制节点切换的能力。

### 高级模式

高级模式开放每个平台的抓取目标、检索并发、LLM 调用并发和 RPM、超时、重试等参数；提供现有 pipeline 参数作为初始参考值，用户可以自行调整。并发和 RPM 控制适用于 App 发起的 LLM 调用，避免不同入口绕过配置。

高级模式与代理开关独立。用户可以在高级模式下直连、使用普通代理，或启用 Mihomo 代理池；不要求先启用代理才能修改深度和并发。仅在选用 Mihomo 时要求相关配置有效，不因高级模式本身强制安装内核。

不设置任务总量、评分岗位数量或 API 费用预算。开启自动评分时，所有通过筛选和去重的新岗位正常评分，用户自行管理 API 花费。RPM、超时和有限重试用于控制运行节奏及可靠性，不代表费用额度。

### Mihomo 代理池

沿用当前 CLI 的独立实例方式：用户安装 Mihomo 并提供可执行文件路径及包含具体 `proxies` 节点的配置文件路径，App 不随包分发内核。首版不支持直接订阅链接、只有 `proxy-providers` 的配置或订阅管理。

App 读取节点后生成临时配置，自动创建专用代理组、监听端口和控制密钥，启动独立 Mihomo 实例。用户无需预先手动创建这些资源，App 不连接或修改用户正在使用的代理实例，也不修改系统代理或全局代理选择。运行结束后关闭自己启动的实例并清理临时配置。

新项目从零实现代理模块，以现有候选检测、出口验证、出口去重、冷却、轮换、退避和失败处理策略，以及 LinkedIn 代理池调度、Indeed 独立执行的基本方式作为行为参考；不要求引用或搬运旧代码，也不随意改变已确认的策略语义。高级设置开放端口数量、每端口并发、轮换批次、冷却、退避、候选检测和重试等现有参数，并提供默认值和简单说明。

启用代理池时，启动前检查可执行文件、具体节点配置和端口可用性，启动后确认控制接口与代理池可工作。失败时明确报错，不静默改为直连；用户可自行关闭代理池再运行。

## 运行计划与进度

无需 Hermes 或其他外部 Agent 即可执行完整 pipeline。运行由「计划」触发，逻辑类似闹钟：

- 可添加多个计划，最多 10 个。每个计划包含开关、要跑的搜索（默认 All searches，可多选具体搜索）、本地时间 HH:mm 和重复的星期；时区使用系统时区并保存在计划中。不选任何星期即「只跑一次」：在下一个该时刻运行后自动关闭，计划保留。
- 一轮运行只跑所选搜索中启用的 query × 城市 × 平台；All searches 跑全部启用搜索。快照记录所选搜索。所选搜索被删除时从计划移除；计划没有剩余搜索时自动关闭并提示。
- 附近（内部按一小时判断）已有其他开启的计划时，编辑页在时间旁提示「Another schedule is due around this time. One of them may wait for the other to finish.」，不写具体计划或时长，允许保存。
- 运行入口：计划详情右上角 Run now（跑该计划所选搜索，不必先保存，新建计划未保存时也可直接试跑）；历史运行详情的 Run again（按该轮所选搜索、使用当前配置再跑一次）；未运行卡片的 Run now。任何运行进行中时这些按钮都不可用并说明原因。顶栏不放运行按钮。

首版支持关闭前端主窗口后驻留后台：Electron main 与 Python service 保持运行，页面未打开时也会按计划到点自动抓取并按开关评分；重新打开可查看进度和结果。点击窗口关闭按钮不退出 App；显式 Quit/Cmd+Q 才完全退出，退出后不继续调度。

后台呈现：

- Dock 图标只在窗口打开时显示，关闭窗口即隐藏；窗口打开时可在 Dock 图标右键退出。
- 菜单栏图标默认显示，空闲与运行中使用不同图标；菜单包含 Open Job Vaccum、当前状态（Idle，或 Running 及进度）和 Quit Job Vaccum。可在 Settings › Appearance 关闭，该开关保存在本机 UI 偏好，不写入业务配置。
- Dock 与菜单栏图标都不显示时，后台照常运行和调度；用户从 Spotlight、Launchpad 或应用程序文件夹再次打开 App 恢复原窗口，打开后用 Cmd+Q 退出。关闭菜单栏图标的开关旁说明这一点。
- 显式退出时，若有运行（包括 stopping），先确认：「A run is in progress. Quitting stops it; finished tasks are kept and you can resume later.」；空闲时直接退出。关闭窗口不弹出提示。电脑休眠、关机或 App 已退出时不运行，也不自动补跑；错过的计划显示为「未运行」，由用户决定是否手动运行（见下）。不为运行阻止系统休眠。首版不包含开机自启。

同一时间只允许一轮运行（抓取或手动评分）。计划到点时若已有运行，本次进入等待，当前运行结束后按到点先后自动开始，不并行。每个计划最多一个等待：它再次到点时旧的等待记为未运行（Waited too long），新的继续等待。等待可在详情中取消（Cancel this run），计划本身不受影响。用户 Stop 只停止当前运行，等待的照常开始。App 退出或崩溃时仍在等待的记为未运行。

未运行：原因为 Mac was asleep、Job Vaccum was closed 或 Waited too long。每个计划只保留最近一条，并显示此前累计错过次数（如「Missed 3 times since 10/14」）。详情提供 Run now 与 Delete；未产生运行数据，删除不需确认。

Runs 页布局：

- 卡片左栏、详情右栏，顶栏只有页面名和计划数。左栏上部为计划区（标题「Schedules」和 + 按钮）：正在运行和等待中的卡片置顶，其余计划按时间从早到晚排序，关闭的计划留在原位、文字变灰。一条分隔线下为历史区，按时间倒序。
- 计划卡片：第一行为所选搜索名称和开关，第二行为时间 · 重复（或 Once）和下一次日期。运行中卡片：搜索名称和任务进度，蓝点 Running；等待卡片：搜索名称，Waiting · due 09:30。
- 历史卡片：第一行为开始时间和新发现数（评分运行为岗位数），第二行为状态圆点、状态和所跑搜索（评分运行写 Scoring completed 等）；不加来源标签，来源（Scheduled／Manual）写在详情副标题。
- 计划详情顺序：开关、搜索（标签多选）、时间、重复（星期标签，提示 No days = run once）；下方说明每轮会跑什么（任务数、各平台条数上限、发布时间范围、自动评分）并链接 Edit searches；再下为最近几次触发结果；底部为时区说明（Runs only while your Mac is awake and Job Vaccum is open or in the background）、Delete、Cancel、Save。
- 运行详情：标题为所跑搜索和状态，副标题为来源与起止时间；运行中右上角为 Stop（停止中为禁用的 Stopping… 并显示仍在进行的任务和模型请求数），结束后为 Run again。统计卡片为 Received、Filtered out、Matched、New jobs：Matched 下以小字写「N seen before」（历史重复，即 Matched − New）；Filtered out 右上角「By rule」打开纵向小卡片，逐条列出各规则筛除数量，只列本轮开启的规则。其下为按搜索统计和任务表。任务表不分页，在表内滚动、表头固定，每行单行显示，长内容截断、悬停看全文；Notes 列由任务统计生成：No results、N without description、Rate limited N×、N warnings，失败时为原因与错误码。
- 配置不完整时左栏顶部提示一行（如「Can't run yet: add a query」）并链接到对应设置，不显示错误码、不用红字；所有运行按钮不可用。

一轮 run 包含所选搜索中全部启用 query × 城市 × 平台任务；每个任务完成即处理入库。运行记录分别展示抓取和评分的任务进度、活跃数，以及新发现、历史重复、筛除、评分成功和评分失败等数量。区分正常零结果、访问失败、部分完成和用户停止。CSV 是按需操作，不是每轮完成的必要阶段。

按方向展示简单统计：抓取条数（含重复）、硬筛除条数、去重后命中岗位数（含已有岗位）。同一岗位可分别计入多个方向，方向计数之和不要求等于全部唯一岗位数。重试不重复累计同一份已处理结果，不为统计保存被筛岗位完整条目。

允许停止并保存已提交进度；已入库并标记成功的抓取任务续跑时跳过，未提交或失败任务从头重抓，不恢复页码/cursor。已入库待评分岗位可直接继续评分，无须等剩余抓取完成。抓取结束后仍须等评分处理完，才确定运行最终状态。用户停止时停止派发及重试；抓取子进程有限等待后终止，已发出的 LLM 请求等待成功或超时，成功评分照常入库，期间显示正在停止及剩余请求数，结束前不启动下一轮。显式退出另设有限等待，超时结束 Python service，保留已提交数据；异常退出的运行标记为中断。运行与任务标识不依赖日期目录，同一天可以在上一轮结束后创建新运行，仍然执行跨运行去重。续跑沿用原业务配置快照，但允许使用修正后的凭据；凭据不写入快照。

用户可以从某次运行打开其发现的岗位。后台执行期间，岗位发现与投递清单仍可正常浏览和操作。

## CSV 导出

岗位发现和投递清单均支持导出当前筛选结果或全部结果。导出基于 SQLite，不依赖中间 JSON 或历史 CSV。

导出对话框分三部分：顶部为格式切换（只有一种格式时隐藏），中间「Jobs」为所有格式共用的范围选择（当前筛选的全部页／全部岗位），下面是当前格式自己的选项。首版只有 CSV；以后增加其他格式时只新增一个格式选项及其参数，不改范围部分。点 Export… 后由系统保存面板选择位置，完成后提示条报告条数并提供 Show in Finder。

采用 UTF-8 BOM，基础字段包括公司、标题、地点、岗位类型、评分、理由、方向标签、来源、发布时间、发现时间和申请链接。投递清单另带状态、备注、加入时间和状态更新时间。

多个方向标签放在同一行中，不因多方向重复导出岗位。导出当前方向时同样保持每个实体一行。完整 JD 作为可选导出项。

不再强制生成四个方向乘 high、mid 的八份 CSV。用户通过界面筛选方向和分数，再按需导出。

## 数据模型与留存

### 逻辑对象

以下是逻辑模型，不要求每项单独建表。核心是一条岗位对应一行岗位记录，完整 JD、公司、标题、地点、当前评分等直接存为该行字段。来源和 query 可以使用 JSON 数组；方向关联和查重身份使用辅助表，不复制岗位或 JD。投递清单是对同一岗位的管理关系，不复制第二份岗位内容。

| 对象 | 主要内容与关系 |
| --- | --- |
| 岗位实体 | 内部 ID、公司、标题、地点、完整 JD、岗位类型、薪资及单位、链接、首次发现时间 |
| 岗位来源 | 平台、平台岗位 ID、规范化链接，关联岗位实体 |
| 搜索方向与 query | 稳定 ID、名称或表达式、启用状态、方向显示顺序 |
| 检索命中关系 | 岗位、query、方向及运行之间的关系；方向标签随重命名或删除同步变化 |
| 评分结果 | 岗位、当前分数、理由、状态、使用的模型 ID、评分时间，以及必要的续跑信息 |
| 投递清单记录 | 唯一岗位 ID、用户状态、备注、加入时间和更新时间 |
| 运行与任务 | 配置快照、阶段状态、任务进度、统计、错误及恢复信息 |
| 配置 | 城市、Indeed 国家、平台、规则、模板、自定义模型连接、运行参数、代理选项和运行计划 |

API Key、Mihomo 控制密钥等不作为可导出的业务数据。具体使用系统凭据存储或其他本地安全存储方式，在实现时确定。

### 核心约束

- 基础去重确认的一个岗位只对应一个实体；多个方向通过关系关联，不复制岗位行。
- 平台身份和有效唯一链接建立适当唯一约束，避免并发写入制造重复实体。
- 每个岗位最多存在一条投递清单记录。
- 重新检索和评分不能覆盖用户的投递状态及备注。
- 移出清单不删除岗位和查重身份；方向排序不改变实体、评分和清单记录。
- 删除方向或 query 不删除岗位或清单；清理运行记录不应删除仍在留存期内或被投递清单引用的岗位，也不应破坏其方向和来源信息。
- 设置页手动清理和 自动清理均保护投递清单引用的岗位及详情；投递清单的批量删除是独立操作。

### 留存与清理

设置页提供「自动清理保留天数」retention_days，默认 14，必须为非负整数；0 表示关闭自动清理，正整数表示保留天数。统一用于未加入投递清单的岗位、运行记录、计划触发记录及日志，不另设多组期限。保存后从下一次清理检查起使用当前值，不立即执行删除、不采用运行快照中的旧值；缩短期限可使已有数据在下一次检查成为清理候选，调长不恢复已删除数据。

设置页手动清理与 自动清理使用相同的保护规则：用户主动加入投递清单的岗位不清理。第二个页面单独提供批量选择和删除（移出清单），不与设置页清理混用：

- 自动清理：从岗位首次发现时间起算，超过配置保留天数且不在投递清单中的岗位，删除其实体、来源、命中关系、评分和查重身份。投递清单中的岗位及其内容、状态和备注保留；重新检索到不延长首次发现时间。
- 设置页手动清理：清理所有未加入投递清单的岗位及关联业务数据，不受保留天数限制；同时清理运行记录、日志和临时数据。保留投递清单中的岗位、完整详情、评分、来源、方向关联、查重身份、状态和备注。执行前明确说明保留投递清单。
- 运行记录和日志按创建时间超过同一配置保留天数后清理。删除运行记录不得级联删除尚未过期或仍在投递清单中的岗位，不破坏保留岗位的来源和方向关联。
- 两种清理均保留用户配置，包括方向、query、城市、规则、模板、模型连接和运行计划；不等同于恢复出厂设置。
- 自动清理在 App 启动及运行期间定期检查，保留天数不是检查间隔。清理与正在执行的任务互斥，运行期间延后执行，避免删除在途任务依赖的数据。

数据库中的每条岗位保留完整 JD 和详情所需字段。JobSpy DataFrame 直接在内存处理，不生成抓取结果 JSON/CSV 文件、manifest 或分页检查点；未入库内存结果在退出/崩溃后丢弃。每个任务的岗位变更、按自动评分开关创建的待评分任务和抓取完成状态原子提交，恢复依赖 SQLite。代理等其他 App 自有临时文件仍按运行结束和统一清理规则处理。配置快照、来源/query 集合等数据库 JSON 字段保持原约定，不属于抓取中间文件。

岗位删除后，其查重身份也删除；以后再次检索到可作为新岗位进入。用户在投递清单页面单条或批量移出岗位，只删除清单关系、状态和备注，不立即删除岗位或查重身份；此后按原首次发现时间参与自动清理，已超过配置保留天数的在下一次清理时删除，也可由设置页手动清理删除。

## 技术基线

| 层次 | 基线选择 | 责任 |
| --- | --- | --- |
| 桌面与界面 | Electron、React、TypeScript | 页面、窗口、后台驻留、桌面交互和计划触发 |
| 业务执行 | Python、JobSpy | 检索、规则筛选、去重、评分、代理调度及数据访问 |
| 持久化 | SQLite，由 Python 统一访问 | 岗位查询、清单状态、运行信息和事务约束 |
| 高级代理 | 用户自行安装的 Mihomo | App 生成临时配置并启动独立实例，沿用现有代理调度策略 |
| AI 服务 | 用户提供的 LLM API | query 和评分模板生成、岗位评分 |

Electron 与 Python 通过受控的进程消息接口交换命令、结果和进度事件。首版不要求另建 HTTP 服务。接口需能区分请求、响应、进度和错误，界面不直接执行任意命令或直接写 SQLite。

检索在独立工作进程执行，LLM 调用在 Python service 内线程池执行，统一限制并发/RPM，避免阻塞 UI 和命令接收。数据库使用索引、短事务和集中协调的写入；等待网络时不保持写事务。按需要采用 WAL 支持执行期间的读取。

使用 Python 和第三方 JobSpy 库。整个产品从零开发，包括抓取封装、筛选、去重、评分、代理模块、持久化、运行组织和桌面界面。现有私人 pipeline 仅用于理解行为和验收对照，不安排代码复用、搬运或原地改造，不导入旧 src 模块，不兼容私人 CLI 的日期目录、旧检查点或固定分类输出。

用户不需要安装 Python 或 JobSpy。发行包只面向 macOS Apple Silicon（arm64），包含相应运行环境；只有启用 Mihomo 代理池才需要用户安装该内核。首版不开发其他系统或 CPU 架构支持。打包工具、最低 macOS 版本、签名与公证流程在发布方案中确定。

开发 UI 时使用样例岗位和模拟运行事件，避免每次调试都抓取网站或调用付费 API。样例不包含开发者私人求职数据。

## 设置分页

| 页面 | 配置内容 |
| --- | --- |
| 搜索方向 | 方向、显示顺序、query、城市、半径、Indeed 国家和平台；可重新通过 AI 生成 |
| 筛选与评分 | 筛除开关、阈值、公司名单、自动评分开关、评分模板及重新生成入口；手动评分在岗位发现和投递清单 |
| 模型连接 | Custom 四种协议、Base URL、Key、模型 ID、可选请求参数和连接测试 |
| 运行与代理 | 默认／高级模式、检索深度、LLM 并发及 RPM、独立代理开关、普通代理和 Mihomo 路径／节点配置／调度参数 |
| 数据清理 | 自动清理保留天数设置（默认 14 天）及下次清理将删除数量的预览、手动清理所有非清单岗位及运行数据；两者均保留投递清单及配置 |
| 外观 | 模式（System／Light／Dark）、浅色主题和深色主题（各自从 Graphite／Pine／Ink 中选）、菜单栏图标开关（旁边说明图标都隐藏时如何重新打开），均存本机 UI 偏好 |
| 关于 | 版本、后台连接状态、数据目录（Show in Finder）、数据库状态、离线诊断；Ping 只在开发构建显示 |

运行计划不在设置中，在 Runs 页管理（见「运行计划与进度」）。

设置页沿用应用外壳：侧边栏选中 Settings，卡片左侧为分区目录，右侧为内容。各分区随所属阶段加入，M1 有搜索方向（改名、拖动排序、删除）、数据清理、外观和关于。改名和保留天数需点 Save 才写入，非法输入在输入框下方提示且不保存。

设置中的 AI 功能复用首次引导能力，不开发第二套配置生成逻辑。重新生成形成草稿，用户应用后才影响正式配置。

## 发行与数据边界

公开产品从当前私人自动化中整理通用能力，不直接发布现有私人仓库。现有 `.env`、个人 rubric 中的经历、账号信息、结果数据、代理节点凭据和 Hermes 上传配置不进入公共发行内容。

模型调用会向用户配置的服务发送完成任务所需的简历、评分模板或 JD，相关输入页需要明确说明。Key 不进入日志、导出文件或诊断截图文本。

保留 JobSpy 及打包依赖所需的版权和许可文本，公开说明检索层基于 JobSpy。Mihomo 首版由用户自行安装；若以后改为随包分发，需重新落实对应版本的发行许可和源码提供要求。

项目自身的开源许可证在发布前确定。产品文案突出集成、AI 配置、评分、可靠运行和桌面体验，不宣称第三方抓取代码为原创。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 首次配置 | 用户自带 Key，完成方向、筛除和评分模板配置并启动一轮搜索 |
| AI 生成 query | 默认一个方向和 2～3 条 query；城市与 query 可修改，保存后在设置中一致呈现 |
| 重新生成模板 | 新结果先成为草稿；未应用前不覆盖用户现有模板 |
| 默认运行 | 无需 Mihomo；Indeed 每任务目标 100、LinkedIn 10，LLM 并发 1，使用固定保守 RPM；网站访问失败与零结果分别显示 |
| 高级运行 | 可修改深度、检索和 LLM 并发／RPM等参数，代理可关闭，不以安装 Mihomo 为前提 |
| Mihomo 代理池 | 用户提供内核和具体节点配置，App 创建独立实例；保留轮换策略，退出清理自己创建的实例和临时配置 |
| 自定义模型 | 四种协议可切换；可选字段留空不发、填写按协议发送，不自动进行模型适配 |
| 地点配置 | 默认美国城市可编辑，Indeed 国家可填写；LinkedIn 只使用 location |
| 多方向命中 | 同一岗位在两个方向可见，「全部」只显示一次，详情保留两个来源方向 |
| 方向排序 | 拖动方向只改变导航顺序，不改变岗位、评分或投递清单 |
| 方向重命名／删除 | 重命名同步显示；删除移除全部对应标签和 query，岗位与清单保留 |
| 历史命中 | 不重复插入或评分，不刷新首次发现时间；补充新方向和来源 |
| 筛除统计 | 被筛岗位直接丢弃，页面按方向展示抓取、筛除和去重后命中数量 |
| 重复加入 | 从不同方向或运行加入同一岗位，投递清单仍只有一条记录 |
| 清单管理 | 修改状态、备注、排序与筛选可持久保存，重新抓取不覆盖用户修改 |
| 批量改状态 | 勾选多条清单岗位一次改为同一状态，备注不变，各条更新时间刷新；已不在清单中的 ID 单独报告 |
| 单条／批量删除清单记录 | 支持勾选、当前页全选和批量移出，不弹确认；删除清单关系及状态备注，岗位和查重身份不立即删除，恢复普通清理规则；提示条 Undo 可完整恢复 |
| 部分失败 | 成功结果可浏览导出，评分失败不记为 0 分，续跑复用成功进度 |
| 计划重叠 | 已有运行时不并行启动第二轮；到点的计划进入等待，前一轮结束后自动开始；每个计划最多一个等待，App 退出时记为未运行 |
| 模板或模型变化 | 已有分数保持，只展示评分时间，不标记过期或自动重评 |
| 手动评分 | 两个页面均可按勾选或当前筛选全部评分，执行前确认数量；使用当前配置更新成功评分；失败保留原分，不改状态和备注 |
| 按批次浏览 | 多选批次只显示这些运行首次发现的岗位，每个岗位只属于一个批次；All 显示全部 |
| 跳过引导 | 各步骤可跳过；无评分模板时自动评分关闭，运行正常完成，新岗位未评分 |
| 后台图标与退出 | 关窗后隐藏 Dock 图标；菜单栏图标可关闭，二者都隐藏时后台照常调度并可从 Spotlight 重新打开；运行中退出需确认 |
| 列表布局 | 两页列宽、显示的列和侧边栏折叠状态重启后保持；列总宽超出时横向滚动；折叠侧边栏后可从方向弹出列表切换方向 |
| 全部新岗位评分 | 开启自动评分时，通过筛选和去重的新岗位均送评，不设置 API 费用或评分额度 |
| CSV 导出 | 当前筛选与全部导出范围准确，多方向实体只导出一行，清单包含状态与备注 |
| 自动清理 | 首次发现超过配置保留天数且未加入清单的岗位及关联数据删除；清单岗位及完整详情保留，重复命中不延长时间 |
| 设置页手动清理 | 清理所有非清单岗位、运行记录、日志及临时文件；清单岗位、完整详情、状态备注及配置保留 |
| 抓取分批入库 | 每个抓取任务返回即处理入库；无抓取中间文件；已提交成功任务跳过，未提交/失败任务从头重抓 |
| 安装运行 | 在支持的 Apple Silicon Mac 上不依赖预装 Python 或 JobSpy；仅 Mihomo 代理池需要外部内核 |
