# 分阶段开发计划

所有阶段均在新工程中从零实现，不改造私人 pipeline。按顺序交付可运行增量；界面可以使用模拟数据提前开发，但不能因此跳过数据库约束或进程可靠性。本文没有授权自动发布、推送或接入私人账号。

## M0：独立工程、通信和打包可行性

依赖：阅读全部文档；确认新工程位置。

任务：

- 前端开始前阅读根 AGENTS.md 指定的 apple-design 与 emil-design-eng skills。M0 仅建立最小窗口、基本布局、样式变量及真实通信状态/错误展示；M1 完成业务浏览闭环，M5 完善完整界面，不提前扩大阶段范围。
- 建立 Electron/React/TS 与独立 Python 包，按 ARCHITECTURE 固定 JobSpy 完整提交 SHA 和依赖 lockfile，记录包版本/SHA及项目启动命令。
- 建立 protocol v1 的 TS 消息类型与 Python 命令入口参数校验，不另建双端 JSON Schema；最小 ready、app.status、可控错误路径。
- 建立最小通信请求/响应样例；完整 fake scraper/fake LLM 分别在 M2/M3 实现。
- 建立 App 数据目录、单实例锁和 SQLite 迁移 001 骨架。
- 制作最小 arm64 安装包，启动随包 Python、导入 JobSpy/curl_cffi 并验证 arm64 原生库收集、完成协议往返和 SQLite 读写，不抓真实网站。
- 维护 dev-docs/DEVELOPMENT-STATUS.md，记录确实运行过的命令、Electron/Python 版本、macOS 版本和安装验证。

交付：可打开的最小桌面 App、模拟 Python 后端、最小安装产物、可重复构建步骤。

出口：移除开发 shell PATH 和项目 .venv 依赖后仍启动成功；协议 chunk/多行/错误处理通过。打包未验证不能进入“只做 UI”的长期开发。

## M1：岗位数据与清单闭环

依赖：M0；DATA-MODEL 与 CONTRACTS。

任务：

- jobs、identities、directions/query、job_directions、applications 的迁移和 repository。
- JobSummary/Detail、扩展 FilterSpec、稳定排序、匹配总数、详情抽屉；CSV 共用筛选查询，applications.add_many 支持逐项结果。
- 窗口外壳按 SPEC「窗口布局与列表」：隐藏原生标题栏，顶栏含红绿灯、侧边栏开关、页面名和操作按钮；可折叠侧边栏（搜索、Jobs/Shortlist/Runs、Searches 方向列表，Settings 与连接状态在底部；折叠为 52px 窄条后搜索和方向为弹出框）；圆角主区域卡片内为筛选行、表格和详情；窄窗口自动折叠侧边栏、详情改为浮层；默认窗口 1280×800，Runs 入口到 M2 再显示。筛选行含选择按钮（全选/取消全部、按条件勾选当前页）、Clear all 和分页（每页 50/100/200）；右下角提示条（可撤销操作带 Undo）；确认框只用于删除搜索方向和清理岗位数据；加载、空结果、请求失败、后台退出和启动失败状态按 SPEC。两页共用表格组件：点击表头排序、评分色块、单行理由、列宽调整与列显示选择、横向滚动，列布局和侧边栏折叠状态保存在本机 UI 偏好；详情抽屉以 Markdown 渲染 JD 并禁用原始 HTML。M0 的 Connection/Status/Diagnostics 移到 Settings › About，Ping 只在开发构建显示；按钮区分主次，每个视图一个实心主按钮；启动失败改为整窗口错误页并提供 Quit；错误先显示原因、代码次要。
- 导入合成岗位，包括一岗多方向/来源、无分、0 分和完整长 JD。
- Shortlist 加入防重、修改状态/备注、逐行选择、当前页全选、批量改状态（applications.set_status）、批量移出（不弹确认），用 applications.restore 撤销移出和批量改状态；状态与备注可在详情和行内编辑。
- 方向改名、排序、删除；Jobs 与 Shortlist 共用内容和详情组件。
- 设置页分区目录：Searches（改名、拖动排序、删除）、Data（保留天数、清理预览、手动清理）、Appearance（System／Light／Dark，浅色、深色各自选择 Graphite／Pine／Ink 主题，颜色以 SPEC 配色表为准，用 CSS 变量实现，替换 M0 的蓝色强调色）、About（版本、数据目录、M0 诊断）。
- 设置页手动清理及自动清理 service，设置可调整 retention_days（非负整数，默认 14；0 关闭自动清理），使用可注入时钟测试默认/自定义期限、0 关闭及重新开启、修改后下一次清理，不等待真实时间。
- CSV 查询与导出，当前筛选导出覆盖全部页；导出对话框按「格式切换 + 共用范围 + 格式选项」组织，首版只有 CSV 时隐藏格式切换。

交付：不访问网络即可演示完整数据管理。

出口：同岗不复制正文；重复加入无覆盖；清理保护清单详情/评分/来源/标签；清理运行数据不影响岗位；重启保留数据；B09–B12、D18、D19 通过。

M1 第 2 步执行确认（2026-10-19）：用户明确将 run_ids 批次筛选留到 M2，不提前建立运行表；其余扩展 FilterSpec 在本步实现。

## M2：配置和默认模式检索

依赖：M1；PIPELINE 前四节。

任务：

- 配置及运行快照保存 auto_score_enabled（默认 true），关闭时岗位 unscored、不建评分任务、不影响运行完成；续跑沿用快照。
- 正式设置、草稿、按字段顺序保存；手动方向/query/城市/Indeed 国家配置。
- 建立 fake scraper，支持成功、零结果、部分结果、失败和延迟。
- 保存 run 全量无秘密快照、稳定任务 ID；创建 runs/tasks/run_jobs。
- 新写锁定提交的 JobSpy 抓取封装和默认串行执行，off/ordinary 两种代理方式；单平台白名单参数、fetch_description、attrs 诊断、标准 logging、缺失值转换及任务级重试按 PIPELINE 执行。
- 新写可配置规则和归一化/去重模块，按行为参考使用合成回归用例。
- 直接处理 DataFrame，不生成抓取中间文件/manifest/分页检查点；区分任务完成、失败、缺 JD 和正常零结果。
- 每个抓取任务完成即串行去重入库，同轮匹配包含已入库岗位；岗位/关联/按自动评分开关创建的待评分任务/统计/完成状态原子提交。先入库代表固定，已有岗位仅补充来源和方向，不改首次发现时间。
- Runs 页面分别展示抓取/评分进度及每方向简单统计；事件驱动刷新，不解析人类日志。
- Jobs 页批次筛选：runs.list 提供 started_at/new_job_count，FilterSpec run_ids 按 is_new=1 匹配，下拉多选（不设 All 项，移除筛选即全部）；「新发现 N」链到该批次。

- 2026-10-20 Runs 设计修正（M2 范围内先做）：运行状态色、卡片式历史、运行详情（By rule 弹出、seen before、任务表不分页表内滚动、Stop／Run again 在详情）、去掉顶部 Next run 横幅和顶栏运行按钮、侧边栏一行状态、全应用数字日期；runs.start/preview 支持 direction_ids，runs 记录 trigger_json，RunSummary 返回 searches/trigger。M7 前左栏计划区只有 + ：打开仅含搜索选择和 Run now 的新建面板（开关、时间、重复、Save 随 M7 加入）。

交付：手动配置少量任务后可抓取、筛选、入库、浏览，无需 LLM 或 Mihomo 即可开发验证。

出口：mock 集成覆盖完整流程；在获得测试条件后用极小范围真实抓取验证两个平台。测试环境访问失败如实报告，不靠扩大规模或无限重试掩盖。

## M3：四协议 Custom、自动评分与手动评分

依赖：M2；CONTRACTS 模型协议部分。

任务：

- 四种直接 HTTP 适配器和 Custom 页面：Base URL、Key、model、可选参数，协议 endpoint 预览。
- Electron safeStorage 凭据路径，测试加密不可用和错误脱敏。
- 建立 fake LLM，支持成功、无效输出、失败和延迟。
- service 内 LLM 线程池及全局并发/RPM，默认 1/10，其他初值见 ARCHITECTURE。
- 手动编辑 rubric；按批次入库后派发评分，与后续抓取重叠；本轮一岗位一评分任务，不做跨岗位输入复用，成功及时持久化。评分输入不含变化的方向/来源集合。
- 四种协议的正常/截断/空响应/错误解析与有限重试。
- 验证自动评分开关；评分模板为空时 auto_score_enabled 只能为 false。
- jobs.score 与两页工具栏 Score 菜单（Score selected / Score all N matching…，后者先确认数量）及详情抽屉单岗位评分；首评与重评同一入口，不受自动开关影响；2026-10-20 界面修正：重评失败显示旧分加橙点、排队/评分中空心描边标记、确认框写重评与未评分数量且不显示模型和主机、无筛选文案、菜单不预选且高亮为浅灰、批次编辑器去掉 All；成功替换当前分，失败保留旧分和时间。

交付：真实业务完整闭环；四协议均有本地假 HTTP server 的契约测试。

出口：0 分和失败区分；空参数不发、temperature=0 正确发送；不按模型适配；换模型或模板不自动重评。真实模型验证需用户提供测试连接，不读取私人 .env；没实际测试的服务明确标注未验证。

## M4：停止、崩溃恢复与运行完整性

依赖：M3；状态机已在 M2/M3 起实现，本阶段集中验证并补齐。

任务：

- 停止派发/重试、取消未发出请求；抓取子进程有限等待后终止，LLM 在途请求等待结束并保存成功评分；stopping 期间不启动下一轮。显式 Quit 有界退出和清理。
- 进程崩溃后 interrupted、任务恢复、显式 resume 新尝试预算。
- 新 run 不覆盖旧 run；单轮互斥；变更命令超时先查状态，不自动重发。
- 批次入库事务前后、评分任务登记/派发/提交、其他临时文件删除处故障注入。
- 工作期间浏览/清单写操作可响应；清理返回 BUSY 而不是并发删数据。
- 抓取无 raw 恢复机制；已提交成功任务跳过，其余从头重抓；已入库岗位可直接恢复评分。代理等临时文件按原规则清理。

交付：无需重抓已提交成功任务、重评已保存成功结果的恢复能力；不恢复尚未入库的内存结果或分页位置。

出口：ACCEPTANCE 的 R 系列全部通过；不得只在正常成功路径上验证。

## M5：AI 引导与完整界面

依赖：M3/M4。

任务：

- 首次引导与 Settings 共用生成、编辑、应用逻辑；每步可 Skip，跳过模型时方向手动填写，跳过 rubric 时关闭自动评分并在检查页显示；之后保存 rubric 时询问是否开启。
- 求职方向文本生成一个方向、2～3 query；可简短追问和手动编辑。
- 粘贴简历文本＋明确条件生成 Markdown rubric；不做文件入口或解析依赖。
- 草稿持久化、重新生成不覆盖、Apply 原子更新；模型失败输入不丢。
- 按 B01–B08 完成批量加入、当前页/Shift 选择、详情前后导航与快捷键、各页筛选记忆、可移除条件、操作后位置保持；后台变化提示刷新，不强制重排，不新增浏览状态表。
- 英文 UI 空状态、错误状态、运行中状态、评分时间、清理范围文案。
- 设置页清理与 Shortlist Remove 分开，确认文本正确。

交付：新用户无需编辑配置文件即可完成一次流程。

出口：模拟 API 可从全新用户数据目录走完整引导；重启恢复草稿；所有业务页使用真实 repository，不仅是 mock 视觉。

## M6：高级参数与 Mihomo

依赖：M4；可在 M5 后接入。

任务：

- 高级参数页面，不把代理开启作为启用高级模式的条件。
- 新实现 Mihomo 独立实例创建、校验、临时资源清理和控制客户端。
- 按 PIPELINE 第七节实现策略，使用假控制接口、假出口检测和可注入时钟测试。
- 检索器接端口调度，参数默认值可改；对新版 requests 网络封装验证工作进程内 HTTP 观测、实际请求计数和 429 退避，不依赖旧 JobSpy 内部 API；不做订阅/provider-only 导入。
- 真实 Mihomo 小范围验证须由用户提供内核与具体节点配置，不读取其他私人代理配置来代替。

交付：高级直连、普通代理、Mihomo 三路径。

出口：出口去重/冷却/在途耗尽再切换/压力退避/端口停用与归还队列可验证；用户原配置不变，失败不静默直连，退出无本 App 遗留实例。

## M7：计划、后台与发行验收

依赖：M5/M6。

任务：

- 多个闹钟式计划（最多 10 个，所选搜索、星期或只跑一次、时间、时区、开关），在 Runs 页管理；幂等触发、冲突进入等待队列（每计划最多一个，退出记未运行）、不自动补跑而记录未运行（可手动运行或删除），DST 用虚拟时钟验证。菜单栏图标开关移到 Settings › Appearance。
- 关闭前端窗口后 main/service/计划时钟驻留，无 renderer 时到点自动运行；Dock 图标仅窗口打开时显示，菜单栏图标默认显示且可在设置关闭（本机 UI 偏好），二者都隐藏时可从 Spotlight 重新打开；运行中 Quit 先确认，显式 Quit 有界停止；不做开机自启。
- 汇总运行清理、配置保存、密钥遮蔽、长列表和长 JD 的端到端验收。
- 最终 arm64 包，独立用户数据路径、无系统 Python 的干净环境验证。
- 许可清单、JobSpy 归属、用户配置说明、LinkedIn 限流提示、Mihomo 配置边界和清理说明。
- 具备用户签名凭据时完成签名/公证；否则交付测试包并明确阻塞项。

交付：可演示的首版与发布说明。

出口：ACCEPTANCE 全部必选项有实际结果；不能用“能在开发机启动”代替安装验收，不自动公开私人仓库。
